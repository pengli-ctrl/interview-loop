# 面试引擎

## 1. 目标

面试引擎负责把“一次面试”拆成可配置、可恢复、可评估的阶段与问题，而不是把整场对话交给模型自由发挥。

核心原则：

- 轮次、阶段、题目计划、追问上限和评分维度来自版本化场景配置。
- 确定性规则决定是否追问、是否进入下一个主问题或下一阶段。
- 模型只负责在当前阶段边界内生成问题文本和复盘内容。
- UI、API 和测试共用同一份场景注册表。

## 2. 场景注册表

配置入口：`interview_loop/scenarios/packs/technical.json`

场景包包含：

- 岗位族、角色、资历、语言和面试官风格；
- 面试轮次和默认时长；
- 阶段名称、说明、题目池、主问题计划、追问上限和时间预算；
- Rubric 维度与权重。

加载时由 `interview_loop/scenarios/registry.py` 校验，避免缺阶段、空题目计划或非法权重进入运行时。

## 3. 当前面试轮次

| 轮次 | 默认风格 | 时长 | 阶段与主问题数量 |
|---|---|---:|---|
| 技术一面 | 温和 | 60 分钟 | 自我介绍(1) / 项目概览(1) / 项目深挖(2) / 基础技术高频题(3) / 简单系统设计(1) / 候选人反问(1) |
| 技术二面 | 压力面 | 60 分钟 | 自我介绍(1) / 项目概览(1) / 项目深度深挖(2) / 进阶技术题(3) / 系统设计(1) / 候选人反问(1) |
| 技术三面 | 压力面 | 60 分钟 | 自我介绍(1) / 重点项目复盘(2) / 技术决策深挖(2) / 团队与工程建设(2) / 战略与业务思考(2) / 候选人反问(1) |
| HR 面 | 温和 | 60 分钟 | 自我介绍(1) / 离职与求职动机(1) / 协作与冲突(1) / 职业规划(1) / 抗压与加班(1) / 薪资预期与反问(2) |

题目数量由 `question_plan` 决定，不能把“每个阶段一题”写死。新增轮次或调整节奏时只需修改场景包并运行配置测试。

## 4. 状态机

```text
当前阶段
  → 当前主问题
    → 候选人回答
      → 满足追问条件？
        ├─ 是：生成追问，followup_count + 1
        └─ 否：进入下一个主问题或下一阶段
  → 当前阶段全部主问题完成
  → 下一阶段
  → 所有阶段完成
  → 生成复盘
```

状态：

- `current_stage_idx`：当前阶段索引。
- `stage_main_index`：当前阶段主问题索引。
- `stage_followup_count`：当前主问题已追问次数。
- `current_question`：当前展示给候选人的问题。
- `messages`：面试官与候选人的完整轮次记录。

## 5. 追问规则

追问由 `interview_loop/core/flow.py` 的确定性规则触发：

1. 当前追问次数未达到该阶段 `max_followups`。
2. 回答去除空白后不少于 40 个字符。
3. 回答中不包含“不知道 / 没做过 / 跳过 / 不了解 / 不会”等明确终止信号。

不满足条件时，直接进入下一个主问题或下一阶段。追问生成时会把上一题、候选人回答和当前阶段边界传给模型，避免跑到后续阶段。

## 6. 问题生成与去重

`interview_loop/core/question_engine.py` 负责：

- 将当前阶段、主问题计划、追问进度、简历上下文、弱项和岗位匹配上下文组织成 Prompt；
- 要求模型只输出题目；
- 通过文本相似度检测重复或高度相似的问题；
- 相似时触发重写，仍失败则使用确定性的兜底追问。

这样模型可以在表达上自适应，但不能突破阶段与题目预算。

## 7. 输入方式

两种输入共用同一套状态机与报告逻辑：

- **语音输入**：浏览录音 → ASR 转写 → 进入答案处理。
- **文字输入**：文本框提交 → 直接进入答案处理。

图书馆、安静环境或麦克风不可用时使用文字输入；语音服务失败也不会阻塞完整面试。

## 8. JD 与简历匹配

匹配入口：`interview_loop/core/job_match.py`

流程：

1. 规范化 JD 和简历文本。
2. 使用技能目录识别标准技能。
3. 计算 JD 与简历的交集、缺失技能和额外技能。
4. 生成风险项和面试重点。
5. 将匹配上下文传入出题 Prompt。

匹配分数：

```text
match_score = 已匹配 JD 技能数 / JD 技能总数 × 100
```

- `good`：70 分及以上。
- `partial`：40–69 分。
- `poor`：40 分以下。

JD 过短时会拒绝匹配。JD 长度足够但不在当前技能目录内时，匹配结果标记为 `unscored`，面试继续，但界面明确提示“技能目录未覆盖，本次不评分”；未上传简历不会阻止面试，但报告会提示无法验证岗位要求。

## 9. 结束与输出

一轮面试可以：

- 自动完成所有阶段；
- 候选人主动点击“结束面试并生成复盘”；
- 在文字或语音中单独回复明确控制短语，如“结束面试”“请结束本轮面试”；普通叙述中出现该词不会触发。

输出包括：

- 表达结构参考分（启发式）、维度权重、优势、风险、证据和行动计划；
- 完整问答记录；
- 薄弱标签与成长趋势；
- JSON 会话；
- Markdown 面试记录，命名格式为：
  `准确时间+面试轮次+面试模式+面试风格.md`

报告评估细节见 [评估体系](evaluation.md)，运行与数据位置见 [运维手册](operations.md)。
