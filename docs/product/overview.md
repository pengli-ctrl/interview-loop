# 产品概览

## 1. 一句话定位

InterviewLoop 是一个面向技术岗位的 AI 面试训练平台：针对目标岗位和候选人简历完成结构化模拟面试，并输出可回溯的问答记录、评分证据和下一步训练计划。

## 2. 用户问题

传统面试准备通常有三类痛点：

- 题库训练缺少岗位上下文和个人经历，回答容易背模板。
- 通用 AI 聊天可以生成问题，但没有稳定阶段、题目预算和追问边界。
- 真人模拟面试成本高，结束后也缺少完整记录和可执行复盘。

InterviewLoop 不试图替代真实面试官，而是提供高频、低成本的训练环境，让候选人可以反复练习同一类能力并观察进步。

## 3. 目标用户

当前最适合：

- 准备技术一面、二面、三面和 HR 面的后端/平台工程师；
- 想围绕真实 JD 和简历进行针对性练习的候选人；
- 需要展示 Agent 工作流、RAG、评测与平台治理能力的技术项目作者；
- 面试辅导、训练营和团队内部学习场景的受控试点。

暂不面向：

- 要求法律意义上招聘决策的生产招聘；
- 需要视频面试、监考或身份认证的场景；
- 完全没有技术背景、需要通用职业测评的用户。

## 4. 核心价值

### 4.1 针对真实上下文出题

JD 与简历会转化为技能匹配、缺失项和风险项，再进入当前阶段的问题生成上下文。

### 4.2 稳定流程而非自由聊天

每轮面试包含配置化阶段、主问题、追问上限和时间预算。模型不能自行跳过阶段。

### 4.3 完整闭环

面试结束后同时生成：

- 表达结构参考分与证据；
- 优势、风险和行动计划；
- 完整问答记录；
- 薄弱标签与成长趋势；
- 可下载 Markdown 文件。

### 4.4 工程可解释

项目不仅展示 UI，还展示：

- 版本化场景配置；
- RAG + BM25 降级；
- Model Gateway 路由和预算；
- AgentRun Trace；
- 工具权限、幂等、超时和审计；
- 黄金数据集、质量校准和 CI。

## 5. 产品边界

- 评分用于训练反馈，不构成真实录用结论。
- 语音是可选输入，文字输入始终可用。
- Demo 模式使用固定数据，仅用于展示和测试。
- 公测前仍需补齐账号、数据库、配额、监控和隐私合规能力。

## 6. 为什么它不只是 Demo

一个普通 Demo 往往只包含“输入问题 → 调用模型 → 展示回答”。InterviewLoop 额外具备：

- 多轮、多阶段、可配置状态机；
- 可测试的追问判定和阶段约束；
- 真实岗位匹配和简历检索降级；
- 结构化报告和成长趋势；
- Agent 运行审计、模型成本控制和工具权限；
- 135+ 自动化测试、GitHub Actions、Playwright 演示断言和 Docker 运行方式。

它仍然是一个持续演进中的产品原型，但已经把“AI 应用”拆成了可以在真实场景中演进的工程系统。

## 7. 扩展方向

按验证顺序，而不是一次性堆功能：

1. 打磨技术面试纵向体验和真实评分质量。
2. 增加更多岗位族和场景包，如数据、产品、运营、校招。
3. 提供训练计划、错题本和周期复练。
4. 在真实用户验证后评估团队空间、企业题库和培训分析。
5. 只有在负载和边界明确后再拆分服务或引入异步任务系统。
